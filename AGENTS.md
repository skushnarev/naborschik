# naborschik

Плагин для Obsidian, который превращает выделенный Markdown в блоки vc.ru и HTML для Дзена и Смартлаба, и кладёт их в буфер обмена. Гипотеза подтверждена: статья вставляется одним копированием и требует минимум ручных правок. Продакшен-плагин живёт в `src/`, прототипы удалены, история осталась в git и `.scratch/`.

Документы: `README.md` (быстрый старт), `PLAN.md` (гипотеза и фазы), `GLOSSARY.md` (термины), `docs/` (процессы и решения), `.scratch/` (спеки и задачи эпиков). Статус только во front matter, смотреть `make status`.
Язык общения для агента - Русский.

## Инварианты

- Сначала гипотеза, потом плагин. Гипотеза подтверждена живым прогоном и публикацией статьи. Плагин делает меню, буфер, уведомление, разбор и адаптеры площадок. Настройки и загрузка картинок отложены до отдельных задач.
- Ядро это чистые функции: `parse` превращает Markdown в `Document`, адаптер площадки превращает документ в payload. Внутри нет Obsidian API. Плагин только оборачивает ядро.
- Веб-версия конвертера в `web/` использует те же `parse` и `PLATFORMS`, что плагин. `make public` собирает один самодостаточный `public/index.html`, без Obsidian и внешних запросов.
- vc.ru получает `text/plain` с блоками `[tool:{...}]`. Дзен и Смартлаб получают `text/html` с читаемым запасным `plain`. Префикс площадки убран, его добавляла только заглушка.
- HTML-мост для vc.ru и поддержка Windows отложены: у vc.ru остаётся только `text/plain`.
- После каждой задачи, которая меняет сборку плагина (`dist/`), патч-версия растёт на единицу: `0.1.1`, `0.1.2` и так далее. Так Obsidian показывает обновление. Минор и мажор меняются ближе к релизу. Веб-версия зависит от плагина, не наоборот: правки только в `web/` и `public/` версию плагина не двигают.
- Заголовок статьи в буфер не входит. Он вставляется в поле заголовка вручную.
- Картинки не загружаются на площадки. Дзен и Смартлаб получают `img` с data URI и шириной, vc.ru получает строку `![[...]]` текстом: настоящего `uuid` для `[media:...]` нет. Ненайденный файл оставляет текст и предупреждение.
- Один блок отдаём читаемым текстом. vc.ru вставляет одиночный `[tool:...]` сырым текстом.
- Секреты, токены и личные данные в репозиторий не попадают.
- Коммиты локальные и атомарные. Push только по согласованию.
- В новых русских текстах не использовать длинные тире. Только дефис или переписанная фраза. Импортированная спека сохраняется как есть.

## Коммиты

Формат: `<type>(<scope>): <текст по-русски>`, Conventional Commits. Тип и скоуп латиницей, точка в конце не нужна.

- Один коммит это одна причина и одна задача. Если коммит создаёт, двигает или закрывает одну задачу, её ID идёт в заголовок: `feat(converter): VC-02 собрать парсер блоков`.
- Диапазон ID (`IMG-01..IMG-04`) и два ID в заголовке запрещены: такой заголовок врёт о границах работы. Несколько задач дробятся на несколько коммитов.
- Планирование эпика, то есть спека и пачка новых задач, идёт без ID задачи: `chore(tasks): завести эпик адаптации картинок`. Отдельного ID у эпика пока нет, его роль играет директория `.scratch/<эпик>/`. Когда переедем на GitHub issues, у эпика появится свой номер.
- Каркас, тулинг и правки без задачи идут без ID: `chore(agents): добавить скиллы`.
- Тело отделяется пустой строкой, пишется по-русски. Нужно, когда название не объясняет причину.

## Проверка

- `make status` - открытые задачи из `.scratch/*/issues/`.
- `make status ARGS="--all"` - включая done.
- `make status ARGS="--area vc-converter"` - по эпику.
- `make status ARGS="--check"` - схема, ссылки, циклы блокировок.
- `make docs-check` - задачи плюс запрет чеклистов и статусов в доках.
- `make core-check` - ядро, адаптеры и веб-конвертер не импортируют `obsidian`.
- `make version-check` - версия в `package.json`, `package-lock.json` и `manifest.json` совпадает; с `ARGS="0.1.5"` ещё и с тегом.
- `make test` - Node-тесты плагина и веб-сборки.
- `make check` - `docs-check`, проверка чистоты ядра, сверка версии, типы, тесты плагина и веб-сборки, сборка.
- `make golden` - пересобрать golden-фикстуры из `src/`.
- `make public` - собрать веб-конвертер в `public/index.html`.
- `make plugin-link VAULT=/путь/к/хранилищу` - собрать плагин и поставить симлинк на `dist/` в хранилище.
- `make agents` - обновить симлинк `.opencode/commands`, после клонирования достаточно одного раза.

## Agent skills

### Issue tracker

Задачи это локальные markdown-файлы в `.scratch/<feature>/issues/`, спеки рядом в `spec.md`. Статус во front matter, читается `make status`. `milestone` отделяет проверку гипотезы (`mvp`) от плагина (`next`) и других площадок (`later`). См. `docs/agents/issue-tracker.md`.

### Triage labels

Пять ролей скиллов сводятся к четырём статусам: `todo`, `doing`, `done`, `blocked`. См. `docs/agents/triage-labels.md`.

### Domain docs

Single-context: `GLOSSARY.md` и `docs/adr/`. См. `docs/agents/domain.md`.

### Раскладка

- `src/` - продакшен-плагин: `core/` разбор и модель, `platforms/` адаптеры, `plugin/` меню и буфер, `main.ts` обвязка.
- `web/` - исходники веб-конвертера: HTML-шаблон, стили и TypeScript-вход.
- `public/` - вывод `make public`, один самодостаточный `index.html`.
- `test/` - Node-тесты ядра, адаптеров и веб-сборки, фикстуры и golden-выходы.
- `bin/` - проверки задач, документации, чистоты ядра, версии и сборка golden и веб-конвертера.
- `.github/workflows/` - CI и релиз в GitHub Actions.
- `dist/` - сборка `main.js` и `manifest.json`, в `.gitignore`.
- `.agents/skills/` - скиллы (Agent Skills), вендор `mattpocock/skills`.
- `.agents/commands/` - слэш-команды, статические обёртки над скиллами.
- `.opencode/commands` - симлинк на `../.agents/commands`, каталог в `.gitignore`.
- Источник один: `.agents/`. Копии по харнесам не заводить.

### Недокументированное API

`MenuItem.setSubmenu()` не входит в официальное API. Правило сверки по рабочим плагинам, объявление типа и откат описаны в `docs/obsidian-api.md`.

## Маршрутизация работы

Скиллы не обязательный ритуал, а короткие переходы между этапами. Подсказывай команду только на границе работы и только если она меняет следующий шаг.

- Спека есть, задачи не нарезаны -> `/to-tickets`.
- Нужно проверить спеку на дыры -> `/grill-me` или `/grill-with-docs`.
- Взяли задачу в работу -> `/implement`.
- Доменный вопрос или спор о терминах -> `/grill-with-docs`.
- Конец крупного среза -> `/retro` или `/handoff`.
- Непонятно, какой флоу выбрать -> `/ask-matt`.

Правила подсказки: максимум одна строка в конце ответа, без абзаца и переспроса. Не повторять команду, если её уже предлагали. Не предлагать посреди задачи.
