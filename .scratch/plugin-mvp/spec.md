> **Дата:** 2026-11-25

## Проблема

Я пишу статью в Obsidian и публикую её на vc.ru, Дзене и Смартлабе. Сейчас у меня две несоединённые половины. Прототип в браузере разбирает Markdown и отдаёт готовый выход, но статью надо копировать туда руками. Плагин в Obsidian знает про выделение, меню и буфер, но только добавляет строку `Для vc.ru` и возвращает Markdown как есть. Чтобы получить верстку, я держу открытыми Obsidian и браузер и переношу текст между ними.

Мне нужен один жест внутри Obsidian: выделил статью, выбрал площадку, вставил в черновик готовые блоки. При этом прототип доказал, что три выхода расходятся сильно: vc.ru хочет `[tool:...]`, Дзен и Смартлаб хотят HTML с разными деградациями. Значит, плагин не может быть одной функцией конвертации. И ещё: Телеграм, Пикабу и Хабр впереди, поэтому новая площадка не должна требовать правок в разборе.

## Решение

Плагин сам делает то, что сейчас делает прототип. Выделение или заметка целиком разбираются в общую модель документа, выбранный адаптер площадки превращает её в буфер. Для vc.ru это `text/plain` с блоками `[tool:...]`, для Дзена и Смартлаба `text/html` с текстовым запасным вариантом. Префикс `Для vc.ru` исчезает: он был нужен только заглушке.

Код переезжает в `src/` на TypeScript, собирается esbuild в один `main.js`, тесты идут в Node без Obsidian. Новая площадка это отдельный модуль адаптера плюс строка в реестре. Разбор, модель и адаптеры не импортируют Obsidian, обвязка плагина не знает, как устроен Markdown.

## Решения по реализации

1. **Язык и сборка.** TypeScript в строгом режиме, esbuild собирает один `main.js`. Проверка типов отдельная, `tsc --noEmit`. Тесты идут на встроенном `node --test` и нативном снятии типов Node 26, без jest, ts-node и vitest. Значит, в коде только стираемый синтаксис: без `enum`, `namespace` и декораторов. `marked` 18.2.1 единственная рабочая зависимость и попадает в бандл; `typescript`, `esbuild` и типы Obsidian это dev-зависимости. Лок-файл коммитится.

2. **Раскладка и артефакт сборки.** Продакшен-код живёт в `src/` у корня репозитория, рядом с манифестом, а не внутри `prototype/`. Прототипы остаются историей и эталоном. Каталог `dist/` содержит `main.js` и копию `manifest.json`. Он в `.gitignore`, `make plugin-link` собирает и ставит симлинк на него. В хранилище попадают только файлы плагина, репозиторий целиком туда не проецируется. `data.json` от Obsidian тоже оказывается в игнорируемом каталоге.

3. **Два шва, третий не нужен.** Первый шов: `parse` превращает Markdown в документ. Второй: `convert` адаптера превращает документ в данные буфера. Обвязка соединяет их и ничего не знает о разметке. Тестируется ровно на этих двух швах.

4. **Модель документа.** Прототипный `Block[]` чистится от полей vc.ru: `subline1`, `lineWrapping`, `media.uuid` уезжают в адаптер. Заголовок получает `level`, а не HTML-имя `style`. У текста и цитаты рядом с `html` появляется `text`: Телеграму и Пикабу нужен читаемый текст, и парсер уже держит исходные инлайн-токены, чтобы не снимать теги повторно. Список получает `ordered` вместо строки `listType`. Форма, которая фиксирует эти решения:

```ts
type Document = { blocks: Block[]; warnings: Warning[] };
type Warning = { code: "image-unresolved" | "table-degraded" | "code-degraded"; message: string };

type Block =
  | { type: "header"; level: 2 | 3; text: string }
  | { type: "text"; html: string; text: string }
  | { type: "list"; ordered: boolean; items: ListItem[] }
  | { type: "quote"; html: string; text: string }
  | { type: "code"; text: string; lang: string }
  | { type: "table"; headers: string[]; rows: string[][]; align: Array<"left" | "center" | "right" | null>; raw: string }
  | { type: "image"; src: string; alt: string; width: number | null; raw: string }
  | { type: "delimiter" };

type ListItem = { html: string; text: string };
type ClipboardPayload = { plain: string; html?: string };
type ConvertContext = { warnings: Warning[]; images?: ImageResolver };
type ImageResolver = (name: string) => { src: string; width: number | null } | null;

interface PlatformAdapter {
  id: string;
  title: string;
  icon: string;
  convert(doc: Document, ctx: ConvertContext): Promise<ClipboardPayload>;
}
```

5. **Асинхронность с первого дня.** `convert` возвращает `Promise`, хотя первый срез резолвится сразу. Чтение картинок из хранилища и загрузка в vc.ru асинхронны, и добавление `async` позже задело бы каждый адаптер, реестр и обвязку.

6. **Разбор сохраняет проверенное поведение.** Frontmatter и H1 отбрасываются. Callout превращается в цитату с жирным заголовком. H4-H6 становятся жирным абзацем. Вложенные списки плоские, вложенность показывает маркер `↳`. Пункты задач сохраняют отметку выполнения. Таблица остаётся отдельным блоком с исходным текстом `raw`. Вики-ссылки не разворачиваются и остаются строкой. Картинка становится блоком только если для неё есть `src`; иначе строка остаётся текстом и появляется предупреждение `image-unresolved`. В MVP резолвера нет, поэтому все картинки остаются текстом, как и в живом прогоне заглушки.

7. **Предупреждения.** Парсер и адаптер пишут в один список `ctx.warnings`. Обвязка показывает одно уведомление с числом, подробности уходят в консоль. Отдельного канала для ошибок нет: пустой результат это не предупреждение, а `Нечего копировать`.

8. **Адаптер vc.ru.** Блоки собираются в строки `[tool:{...}]` через пустую строку. Одиночный блок отдаётся читаемым текстом: vc.ru не создаёт нативный блок из одной строки. Таблица уходит как `[code:...]` с `lang: ""`. Цитата получает `subline1: ""`. Картинка без загрузки уходит текстом `![[...]]`. `html` не заполняется, выход только `plain`.

9. **Адаптер Дзена.** Выход повторяет проверенный `toDzenHtml`: код становится цитатой с `<br>`, таблица списком пар, разделитель абзацем `* * *`, H2 и H3 остаются собой, картинка с `src` становится `<img>`. `plain` это читаемый текст без тегов, чтобы вставка в текстовое поле не показывала разметку. Заголовок статьи не входит.

10. **Адаптер Смартлаба.** Выход повторяет `toSmartlabHtml`: H2 в `<h3>`, H3 в `<h4>`, код в `<pre>` без `<code>`, таблица `<table>` с `thead` и `tbody`, разделитель `<hr>`. Без классов, `id` и стилей. `plain` тоже читаемый текст.

11. **Буфер.** Один модуль обвязки. Если `html` есть, пишем `ClipboardItem` с `text/html` и `text/plain`, иначе `writeText(payload.plain)`. При ошибке или отсутствии `ClipboardItem` откат на `writeText(payload.plain)`. Падение буфера даёт уведомление, исключение не выходит наружу.

12. **Реестр площадок.** Упорядоченный список `vc.ru`, `Дзен`, `Смартлаб`. Подменю и команды палитры строятся из него, поэтому название и иконка живут в адаптере. Добавление площадки: модуль адаптера, строка в реестре, файл тестов. Разбор и обвязка не меняются.

13. **Пустой результат.** После разбора нулевое число блоков даёт уведомление `Нечего копировать`, буфер не трогается. Проверка идёт по документу, а не по исходной строке: заметка из одного frontmatter и H1 тоже пустая.

14. **Уведомления.** Успех: `Скопировано для vc.ru, символов: 1234`. С предупреждениями добавляется `, предупреждений: 2`. Считаются символы `payload.plain`, то есть то, что реально попало в буфер.

15. **Чистота ядра.** Импорт `obsidian` разрешён только в модулях обвязки. Проверка механическая: `make check` падает, если импорт нашёлся в разборе, модели или адаптерах. Правило перестаёт быть комментарием.

16. **Проверки и хук.** `make check` это `docs-check`, проверка чистоты, `tsc --noEmit`, тесты и сборка. Сборка в проверке ловит ошибки бандла, которые не видит `tsc`. `make hooks` ставит `.git/hooks/pre-commit` с `make check`. Это закрывает долг ретро про непрогоняемые проверки.

17. **Манифест.** Версия поднимается до `0.1.0` в задаче, которая впервые даёт настоящее копирование. `id: naborschik`, `isDesktopOnly: true`, `minAppVersion: 1.5.0` без изменений. Тип для недокументированного `setSubmenu` объявляется через расширение модуля `obsidian` как необязательный метод, вызов остаётся под проверкой во время выполнения.

18. **Судьба прототипов.** `prototype/` остаётся страницей-эталоном с прежними тестами. `prototype/obsidian/` становится архивом: README помечает его историческим, установка из него больше не описывается, симлинк в хранилище переводится на `dist/`. Удалять прототипы в этом эпике не нужно.

## Решения по тестам

Хороший тест здесь смотрит только на внешнее поведение: Markdown на входе, готовая строка на выходе. Внутренние помощники, порядок вызовов и промежуточные структуры не проверяются, иначе тесты начнут запрещать рефакторинг.

- **Разбор.** Фикстуры покрывают то, что уже проверено на живых статьях: frontmatter, H1, H2 и H3, H4-H6, абзац с инлайн-разметкой и символами `& < >`, callout, обычную цитату, вложенный список, пункты задач, нумерованный список, разделитель, таблицу с выравниванием, код в `~~~`, вики-ссылку, embed картинки без резолвера, пустой вход. Ожидание это документ целиком, без проверки внутренних полей вроде номеров плейсхолдеров.
- **Адаптеры.** Golden-строки на каждую площадку. Эталоны снимаются с прототипа на тех же фикстурах и коммитятся, новый код обязан воспроизвести их побайтно. Это и есть проверка, что переезд не изменил выход.
- **Инварианты.** Документ со всеми типами блоков прогоняется через каждый адаптер, чтобы новый тип блока не остался без ветки. Отдельно проверяются одиночный блок vc.ru, деградация таблицы и кода в Дзене, карта заголовков и `<pre>` Смартлаба, экранирование и отсутствие сырых `[text:` в готовой строке.
- **Предупреждения.** Проверяется, что картинка без резолвера даёт `image-unresolved`, таблица в Дзене даёт `table-degraded`, а успешный разбор без деградаций не даёт ничего.
- **Чистота.** Отдельная проверка на импорт Obsidian в ядре, запускается из `make check`.
- **Обвязка.** Юнит-тестами не покрывается: меню, буфер и `Notice` живут в Obsidian. Её проверка это живой прогон в отдельной verification-задаче, по правилу из ретро.
- **Предыдущий опыт.** Образец это `prototype/tests/*.test.mjs`, 40 тестов на `node --test` и фикстуры `prototype/fixtures/`. Формат остаётся, меняется язык и место.

## Критерий готовности

- Плагин собирается, ставится одной make-целью и грузится в Obsidian из `dist/`.
- Меню и палитра отдают три площадки, каждая кладёт готовый выход без префикса.
- Выход vc.ru побайтно совпадает с проверенным `toVcruPayload` на общих фикстурах.
- Дзен и Смартлаб пишут в буфер HTML, вставка в живой черновик проверена.
- Пустое выделение и пустая заметка ведут себя как описано, буфер не затирается.
- `make check` зелёный и включает типы, тесты, сборку и проверку чистоты ядра.
- Прототипы остались на месте, README и глоссарий описывают новую раскладку.
- Заметка живого прогона заполнена.

## Дальше

**Раскладка.** Продакшен-код живёт в `src/` у корня репозитория, а не внутри `prototype/`. Прототипы остаются историей и эталоном, их структура не меняется. Сборка уходит в `dist/`, манифест лежит у корня и копируется в сборку:

```text
src/
  main.ts                 плагин: загрузка, команды, событие меню
  plugin/menu.ts          подменю и плоский откат
  plugin/clipboard.ts     запись payload в буфер
  core/types.ts           Document, Block, ClipboardPayload, Warning
  core/parse.ts           Markdown в Document
  platforms/index.ts      упорядоченный реестр площадок
  platforms/vcru.ts       Document в [tool:...]
  platforms/dzen.ts       Document в HTML для Дзена
  platforms/smartlab.ts   Document в HTML для Смартлаба
test/
  fixtures/               входные статьи и golden-выходы
dist/                     main.js и manifest.json, в .gitignore
manifest.json             источник, копируется в dist
```

Граница проходит по каталогам: `core/` и `platforms/` не импортируют `obsidian`, `main.ts` и `plugin/` не импортируют `marked`. Новая площадка добавляет файл в `platforms/` и строку в реестре, больше ничего не двигается.

**Порядок работ.** Сначала каркас и переезд заглушки на TypeScript, чтобы сборка и установка из `dist/` проверялись на уже работающем поведении. Потом модель и разбор. Потом три адаптера. Потом переключение обвязки на адаптеры: здесь исчезает префикс и появляется HTML. Потом живой прогон и доки. Долги ретро идут отдельной задачей и не блокируют остальное.

**Риски и откаты.**

- `navigator.clipboard.write` с `ClipboardItem` проверен в Chromium прототипа, но не в Electron Obsidian. Если rich-вставка не сработает, откат на `writeText` с HTML-строкой, как в прототипе, и запись исхода в заметку.
- Читаемый `plain` для Дзена и Смартлаба отличается от прототипа, где в `text/plain` уходил HTML. Если живой черновик покажет неформатированный текст, возвращаем HTML в `text/plain` и фиксируем это как решение.
- Obsidian кэширует `main.js`. Перезагрузка плагина или приложения остаётся в README.
- `setSubmenu` по-прежнему недокументирован. Тип объявлен необязательным, откат на плоские пункты сохраняется.
- Расхождение с прототипом при переезде ловится golden-тестами.

**Открытые вопросы.**

- Одиночный блок vc.ru отдаётся текстом. Если после MVP окажется, что короткие заметки вставляются хуже, правило пересматривается отдельной задачей.
- Нужен ли адаптеру признак «умею картинки», чтобы не читать файлы для vc.ru. Решается в `PL-13` по реальной стоимости чтения, а не заранее.
- Формат предупреждений может измениться после первого живого прогона: число в уведомлении уже есть, подробности пока в консоли.

**Отношение к другим эпикам.** `vc-mvp` и `platforms` остаются источником проверенного поведения и golden-эталонов. `plugin-prototype` закрыт и даёт рабочую обвязку меню и буфера. `PL-13` расширяет этот MVP, а не переписывает его.
