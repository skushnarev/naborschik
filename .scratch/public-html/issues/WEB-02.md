## Проблема

В веб-конвертере `![[...]]` остаются текстом: браузер не видит хранилище Obsidian. Пользователь может выбрать файлы картинок вручную, как открывает `.md`, но непонятно, как связать имена из Markdown с файлами и где хранить картинки до копирования или перезагрузки страницы.

## Решение

Решение принято 2026-11-27. Ниже что выбрано, что отвергнуто и почему. Реализация сделана 2026-11-27.

### Как добавлять файлы

- Кнопка «Добавить картинки» с выбором нескольких файлов.
- Кнопка «Папка» через `webkitdirectory`: даёт относительные пути для уточнения совпадений.
- Перетаскивание файлов на страницу.
- Вставка из буфера не используется: скриншот приходит без имени и не сопоставится с `![[...]]`.

### Как сопоставлять

- Нормализация: регистр, обратные слэши, ведущий `./`.
- Сначала путь, если браузер его дал, потом уникальное имя файла.
- Два выбранных файла с одинаковым именем дают предупреждение и не подставляются. Угадывать файл нельзя.
- Несопоставленная вставка остаётся текстом с текущим предупреждением `image-unresolved`.
- Файлы с другими расширениями отбрасываются с сообщением.
- Ручной выбор файла под конкретную вставку отложен.

### Где хранить

- data URI в памяти, выбрано. Плюсы: тот же формат, что уходит в payload, одна копия, ноль зависимостей. Минусы: base64 добавляет треть к размеру, после перезагрузки файлы выбираются заново.
- object URL отвергнут. Экономнее в памяти, но его нельзя положить в payload, придётся отдельно собирать data URI и держать два представления.
- IndexedDB отвергнут. Переживает перезагрузку, но добавляет схему, квоты и очистку, по-разному работает на `file://`, а опубликованная страница начала бы хранить чужие фото.
- OPFS отвергнут. Быстрее на больших файлах, но лишний API ради двух-трёх фото и ограничения на `file://` и в Safari.
- Сохранения между перезагрузками нет. Markdown тоже не сохраняется, поведение одинаковое.
- Суммарный вес показан. Выше 20 МБ мягкое предупреждение без блокировки: сжатие это `IMG-01`.

Вес собранной страницы не растёт: картинки читаются во время работы, а не встраиваются в `public/index.html`.

### Что уходит в выход

- Дзен и Смартлаб получают `<img>` с data URI.
- vc.ru оставляет строку `![[...]]` текстом.
- Ширина берётся из `|N`, иначе из заголовка файла.
- Картинки никуда не загружаются, запросов в сеть нет.

### Интерфейс

- Строка «Картинки» под полем Markdown: кнопки, плашки `имя, размер, ×`, счётчик «сопоставлено 2 из 3», список несопоставленных имён.
- В предпросмотре блока рисуется настоящий `img`.
- «Очистить» чистит Markdown и картинки. Открытие другого `.md` набор не сбрасывает.

### Пример

Встроенная `star.png` из `test/fixtures` (106 байт) доступна только в режиме примера: первый экран сразу показывает картинку и data URI. Свой файл с тем же именем её перекрывает, при «Очистить» и открытии своего `.md` встроенная картинка уходит.

### Локально и на хостинге

Поведение одинаковое: файлы читаются в память, никуда не отправляются и не сохраняются. Отдельного режима для опубликованной версии нет.

### Версия

Патч плагина не поднимается: `dist/` не меняется. Веб-версия зависит от плагина, не наоборот. Правило в `AGENTS.md` уточнено.

- Показывать предупреждения о ненайденных и неоднозначных картинках.
- Добавить Node-тесты матчера и `convertMarkdown` с резолвером, проверить, что golden не ломается.
- Обновить `spec.md`, `README.md` и записать итог.
- Прогнать живую проверку в Chrome на статье с двумя-тремя фото.

## Приёмка

- Есть сравнение вариантов с плюсами и минусами: записано в «Решении».
- Файлы сопоставляются по имени и пути, одинаковые имена дают предупреждение.
- Дзен и Смартлаб получают `img` с data URI, vc.ru сохраняет строку `![[...]]`.
- Без файла вставка остаётся текстом и даёт `image-unresolved`.
- После перезагрузки картинки исчезают, это ожидаемо и записано.
- Страница не делает запросов в сеть и не загружает картинки на площадки.
- Выходы `WEB-01` и golden плагина не изменились.
- Живая проверка в Chrome на статье с двумя-тремя фото пройдена.
- `make check` зелёный.

## Вне рамок

- Сжатие, адаптация больших фото и лимиты площадок: это `.scratch/image-adaptation/` и `IMG-01`.
- CDN, оптимизация форматов и responsive images.
- Загрузка картинок на площадки.
- Сохранение картинок между перезагрузками.
- Ручное сопоставление файла с конкретной вставкой.
- Вставка картинок из буфера обмена.
- Перетаскивание папок: пути даёт только кнопка «Папка».
- HEIC и другие форматы вне списка `isImagePath`.
- Хостинг и деплой: это `WEB-03`.

## Итог

- `convertMarkdown` принимает необязательный `ImageResolver` и передаёт его в `parse`. Без резолвера поведение прежнее, golden не меняется.
- `web/images.ts` - чистый матчер: нормализация регистра, слэшей и ведущего `./`, поиск по пути, затем по уникальному имени, отказ при одинаковых именах, объединение набора и сводка для интерфейса. Резолвер кэширует ответы по цели вставки, `main.ts` переиспользует его, пока набор файлов не изменился.
- `web/sample.ts` хранит встроенную `star.png` как data URI и собирает запись режима примера. Тест сверяет data URI и вес с `test/fixtures/star.png`. В примере картинка стоит отдельным абзацем, поэтому первый экран сразу показывает `img` и data URI.
- В `web/main.ts` добавлены кнопки «Добавить картинки» и «Папка», drag&drop, плашки `имя, размер, ×`, счётчик «сопоставлено N из M», список ненайденных, предупреждение о любых одинаковых именах и мягкое предупреждение выше 20 МБ. Файлы читаются через `File.arrayBuffer`, data URI живёт в памяти. Предпросмотр блока рисует настоящий `img`.
- Свой файл с тем же именем перекрывает встроенную картинку примера. Своя статья вытесняет режим примера: встроенная картинка уходит, как только текст перестал совпадать с примером. «Очистить» чистит Markdown и картинки, открытие своего `.md` убирает только встроенную.
- Node-тесты: матчер, неоднозначность, объединение набора, сводка, встроенная картинка, `convertMarkdown` с резолвером и пустым резолвером на golden.
- Живая проверка в Chrome через DevTools Protocol: пример сразу показал `img` и «сопоставлено 1 из 1». Своя статья убрала встроенную картинку. Два выбранных файла дали 2 плашки и «сопоставлено 2 из 3», `missing.png` остался текстом с предупреждением. Дзен и Смартлаб получили два `img` с data URI и шириной 64, vc.ru сохранил `![[star.png|64]]` и `![[missing.png]]`. Два файла с именем `dup.png` дали предупреждение и не подставились по имени. «Очистить» убрала плашки и предпросмотр.
- `make check` зелёный: 110 тестов плагина и 40 тестов прототипа. Версия плагина не менялась: `dist/` и `manifest.json` не тронуты.
