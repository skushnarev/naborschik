# Спека: веб-версия конвертера в `public/`

> **Дата:** 2026-11-27
> **Основа:** `prototype/index.html`, `src/core/parse.ts`, `src/platforms/`.
> **Связанное:** `.scratch/platforms/spec.md`, `.scratch/release/spec.md`.

## Проблема

Прототип показывает, как конвертер работает в браузере, но живёт отдельно: свой `converter.js`, `vendor/marked` и вкладка «Проверки». Продакшен-ядро и адаптеры используются только в плагине Obsidian. Чтобы проверять выход без Obsidian и получить страницу, которую можно открыть или выложить, нужна веб-версия на тех же `parse` и `PLATFORMS`.

## Решение

Исходники страницы лежат в `web/`: HTML-шаблон, стили и TypeScript-вход. `make public` собирает их через esbuild вместе с `src/core` и `src/platforms` в один самодостаточный `public/index.html`. Скрипты и стили встроены, внешних запросов нет, страница открывается двойным кликом.

Интерфейс повторяет рабочий прототип без вкладки «Проверки»: Markdown, выбор площадки, предпросмотр блоков, payload, копирование, открытие `.md`, пример и очистка. Заголовок статьи в буфер не входит.

Веб-версия зависит от плагина, не наоборот: `parse` и `PLATFORMS` общие, отдельной версии у страницы нет. Правки только в `web/` и `public/` не двигают версию плагина.

## Что входит

- Один самодостаточный `public/index.html` из `make public`.
- Поле Markdown, открытие `.md`, пример, очистка.
- Три площадки из `PLATFORMS`: vc.ru, Дзен, Смартлаб.
- Вкладки «Блоки» и «Payload».
- Копирование vc.ru текстом, Дзена и Смартлаба rich HTML с запасным plain.
- Выбор файлов картинок, сопоставление с `![[...]]` и data URI в памяти.
- Статистика и предупреждения `parse` и адаптеров.
- Node-тесты сборки и связки веб-конвертера с ядром.

## Что не входит

- Хостинг, домен и деплой: это `WEB-03`.
- Вкладка «Проверки» из прототипа.
- Экспорт из Obsidian.
- Публикация через API площадок.
- CMS, аккаунты и серверный рендеринг.
- Сжатие, адаптация и лимиты картинок: это `IMG-01`.
- Сохранение картинок между перезагрузками и ручное сопоставление файла с конкретной вставкой.

## Картинки

Браузер не видит хранилище Obsidian, поэтому файлы картинок выбирает пользователь. Кнопка «Добавить картинки» открывает выбор нескольких файлов, кнопка «Папка» даёт относительные пути через `webkitdirectory`, файлы можно перетащить на страницу. Вставка из буфера не используется: скриншот приходит без имени и не сопоставится с `![[...]]`.

Сопоставление идёт по нормализованным данным: регистр, обратные слэши и ведущий `./` приводятся к одному виду. Сначала проверяется путь, если браузер его дал, потом уникальное имя файла. Два выбранных файла с одинаковым именем дают предупреждение и не подставляются: угадывать файл нельзя. Несопоставленная вставка остаётся текстом с текущим предупреждением `image-unresolved`. Файлы с другими расширениями отбрасываются с сообщением. Ручной выбор файла под конкретную вставку отложен.

Байты читаются через `File.arrayBuffer`, `toImageAsset` из ядра собирает data URI и ширину. Набор живёт в памяти страницы. После перезагрузки файлы выбираются заново: Markdown тоже не сохраняется, поэтому поведение одинаковое.

Почему не другие варианты:

- object URL экономнее в памяти, но его нельзя положить в payload, придётся отдельно собирать data URI и держать два представления;
- IndexedDB переживает перезагрузку, но добавляет схему, квоты и очистку, по-разному работает на `file://`, а опубликованная страница начала бы хранить чужие фото;
- OPFS быстрее на больших файлах, но это лишний API ради двух-трёх фото и ограничения на `file://` и в Safari.

Выход не меняется: Дзен и Смартлаб получают `<img>` с data URI, vc.ru оставляет строку `![[...]]` текстом. Ширина берётся из `|N`, иначе из заголовка файла. Картинки никуда не загружаются, запросов в сеть нет.

Интерфейс показывает строку «Картинки» под полем Markdown: кнопки, плашки `имя, размер, ×`, счётчик «сопоставлено 2 из 3» и список несопоставленных имён. В предпросмотре блока рисуется настоящий `img`. «Очистить» чистит и картинки, открытие другого `.md` набор не сбрасывает. Суммарный вес показан. Выше 20 МБ появляется мягкое предупреждение без блокировки.

В режиме примера доступна встроенная `star.png` из `test/fixtures` (106 байт): пример сразу показывает картинку и data URI. Свой файл с тем же именем её перекрывает, при «Очистить» и открытии своего `.md` встроенная картинка уходит.

Страница, открытая локально, и страница на хостинге ведут себя одинаково: файлы читаются в память, никуда не отправляются и не сохраняются. Отдельного режима для опубликованной версии нет.

## Открытые вопросы

- Где хостить страницу и коммитить ли собранный `public/index.html`. Решение в `WEB-03`.

## Задачи

- `WEB-01` - собрать веб-версию конвертера.
- `WEB-02` - выбрать и внедрить загрузку и хранение картинок.
- `WEB-03` - выбрать хостинг и деплой.

`WEB-02` идёт после `WEB-01`, когда понятна форма страницы. `WEB-03` идёт после `WEB-01` и не меняет интерфейс.

## Критерий готовности

- `make public` собирает `public/index.html`.
- Страница открывается без Obsidian, сервера и сети.
- Все три площадки дают тот же выход, что плагин.
- Выбранные картинки уходят в Дзен и Смартлаб как `img` с data URI, vc.ru сохраняет строку `![[...]]`. Без файла остаётся текст и предупреждение.
- `make check` зелёный.
