# Спека: Markdown в блоки vc.ru, MVP

> **Статус:** черновик под прототип. Наивная реализация.
> **Дата:** 2026-11-23
> **Основа:** `spec.html` в этой папке, разделы про `[tool:{...}]` и маршрутизацию вставки.
> **Связанное:** `Блог/Пайплайн.md`, пункты E8 и E9.

## 1. Задача

Из выделенного в Obsidian Markdown получить в буфере набор блоков, который вставляется в пустой текстовый блок черновика vc.ru и превращается в готовую верстку.

Заголовок статьи в буфер не входит. Он вставляется в поле заголовка вручную.

## 2. Границы MVP

Делаем:

- заголовки H2 и H3;
- абзацы с жирным, курсивом и ссылками;
- плоские списки;
- цитаты, включая callout-ы;
- разделители;
- блок кода как `code`, язык из fence;
- таблицу как `code` с Markdown-текстом, моноширинно;
- строки картинок как есть, без обработки.

Не делаем:

- загрузку и вставку картинок;
- mark, strike, подсветку;
- таблицы как нативные таблицы;
- вложенные списки;
- предупреждения, валидацию, проверку исходника;
- заголовок статьи;
- HTML-мост из `spec.html` (отложен до Windows).

## 3. Поток

1. Выделить текст в Obsidian, скопировать.
2. Открыть страницу-прототип, вставить Markdown.
3. Нажать «Скопировать для vc.ru».
4. В черновике vc.ru поставить курсор в пустой текстовый блок.
5. Вставить.

Если курсор стоит не в пустом текстовом блоке, vc.ru склеит всё в один блок. Это поведение площадки, а не конвертера.

## 4. Вход

- Markdown из режима редактирования Obsidian.
- Frontmatter в начале файла вырезается, если попал в выделение.
- HTML на входе не поддерживается. Если пришёл HTML, он уходит как обычный текст.

## 5. Выход

`text/plain`, блоки через пустую строку, каждый блок одной строкой.

```
[header:{"text":"Глава 1","style":"h2"}]

[text:{"text":"<p>Абзац с <b>жирным</b> и <a href=\"https://ya.ru\">ссылкой</a></p>"}]

[list:{"type":"UL","items":["Раз","Два"]}]

[quote:{"text":"<p>Цитата</p>","subline1":""}]

[code:{"text":"const x = 1;","lang":"javascript","lineWrapping":false}]

[delimiter:{"type":"default"}]
```

`text/html` в MVP не пишем. На macOS достаточно plain-пути, а HTML-мост из спеки не проверен живой вставкой. Добавим, если понадобится Windows.

## 6. Таблица преобразования

| Вход                | Выход                             | Примечание                             |
| ------------------- | --------------------------------- | -------------------------------------- |
| H1                  | ничего                            | заголовок вставляется вручную          |
| H2                  | `header`, `style: h2`             |                                        |
| H3                  | `header`, `style: h3`             |                                        |
| H4-H6               | `text`, весь текст жирным         | уровень теряется                       |
| Абзац               | `text`                            | инлайн по правилам раздела 7           |
| Плоский список      | `list` UL или OL                  |                                        |
| Вложенный список    | `list`, пункт с маркером `↳`      | vc.ru срезает отступы, вложенность видна маркером |
| Список задач        | `☐` и `☑` в тексте пункта         |                                        |
| Цитата              | `quote`                           | `subline1` пустой                      |
| Callout             | `quote`                           | маркер `[!type]` убирается             |
| `---`, `***`, `___` | `delimiter`                       |                                        |
| Блок кода           | `code`, `lang`, `lineWrapping`    | кавычки убираются, текст как есть      |
| Таблица             | `code`, `lang: ""`                | Markdown-таблица моноширинно, разделитель сохраняется |
| Картинка            | `text`, строка как есть           | ничего не меняем                       |
| Встроенная заметка  | `text`, строка как есть           | ничего не меняем                       |
| Вики-ссылка         | текст или алиас                   |                                        |
| `==x==`             | `x`                               | разметка убирается                     |
| `~~x~~`             | `x`                               | разметка убирается                     |
| `%%x%%`             | ничего                            |                                        |
| `^block-id`         | ничего                            |                                        |
| `#tag`              | `#tag`                            | остаётся текстом                       |

## 7. Инлайн-разметка

Внутри поля `text` собираем HTML для `<p>`:

- `<strong>` → `<b>`;
- `<em>` → `<i>`;
- `<a href="...">` оставляем как есть;
- `<del>`, `<s>`, `<mark>` → только текст;
- `&`, `<`, `>` экранируем как `&amp;`, `&lt;`, `&gt;`;
- перенос строки внутри абзаца → `<br>`;
- пустые абзацы пропускаем.

Поле `text` всегда оборачивается в `<p>...</p>`. Это проверяется на первом прогоне: если vc.ru оборачивает повторно, обёртку убираем.

## 8. Спецразметка Obsidian

- `[[Заметка|алиас]]` → `алиас`.
- `[[Заметка]]` → имя заметки без пути и без `.md`.
- `[[Папка/Заметка]]` → `Заметка`.
- `![[file.jpg|800]]` → строка без изменений, уходит как текст.
- `![[Заметка]]` → строка без изменений, уходит как текст.
- `%%комментарий%%` → удаляется.
- `==текст==` → `текст`.
- `~~текст~~` → `текст`.
- `> [!note] Заголовок` → цитата, маркер убран, `Заголовок` жирным первым.
- `^block-id` → удаляется вместе с пробелом перед ним.

## 9. Одиночный блок

Если на выходе получился ровно один блок, plain-путь vc.ru вставит его сырым текстом. Поэтому для одного блока отдаём читаемый текст без обёртки `[tool:...]`:

- абзац → текст абзаца;
- заголовок → текст заголовка;
- список → пункты с `- ` в начале строки;
- цитата → строки с `> ` в начале;
- разделитель → `***`.

Ограничение осознанное. Если это мешает, выделяй больше одного блока.

## 10. Что проверить на первом прогоне

| № | Вход | Ожидание |
|---|---|---|
| 1 | один абзац | один текстовый блок |
| 2 | `## Глава` и `### Раздел` | два блока header, h2 и h3 |
| 3 | `#### Мелкий` | текстовый блок, весь жирный |
| 4 | абзац с `**жирным**`, `*курсивом*`, `[ссылкой](https://ya.ru)` | b, i, a на месте |
| 5 | абзац с `&`, `<`, `>` | символы видны, теги не создаются |
| 6 | список `-` | list UL |
| 7 | список `1.` | list OL |
| 8 | вложенный список | плоский list, вложенность маркером `↳` |
| 9 | цитата `>` | quote |
| 10 | callout `> [!note]` | quote без маркера |
| 11 | `---` | delimiter |
| 12 | `![[file.jpg\|800]]` | текстовый блок со строкой как есть |
| 13 | блок кода с языком | `code`, `lang` из fence, текст как есть |
| 14 | таблица Markdown | один `code` с таблицей и `lang: ""` |

Дополнительно прогнать на трёх реальных файлах: `016`, `010`, `017`.

## 11. Известные ограничения

- Картинки не загружаются. Строка остаётся в тексте, замена ручная.
- Таблица это `code` с Markdown-текстом, а не нативная таблица. Редактировать её в vc.ru неудобно.
- Неизвестный язык кода уходит в `lang` как есть. Если vc.ru его не знает, подсветки не будет.
- Вложенность списков показывается маркером `↳`, потому что vc.ru срезает отступы.
- Mark и strike теряют оформление.
- H4-H6 становятся жирным абзацем.
- Один блок вставляется текстом, без нативного блока.
- Windows не поддерживается, пока не проверен HTML-мост.
- Длинная статья может вставляться с задержкой. При проблемах резать по H2.

## 12. Каркас

```
src/
  types.ts       Block и вспомогательные типы
  preprocess.ts  frontmatter, комментарии, вики-ссылки, callout-ы
  parse.ts       marked плюс разбор DOM в Block[]
  vcru.ts        Block[] в строку payload
  clipboard.ts   запись text/plain
prototype/
  index.html     textarea, предпросмотр блоков, кнопка копирования
  converter.js   чистые toBlocks и toVcruPayload
  app.js         оболочка страницы
  vendor/        marked локальным файлом
tests/
  fixtures/      три реальных файла плюс синтетика на края
```

Две функции, вокруг которых всё крутится:

```ts
toBlocks(markdown: string): Block[]
toVcruPayload(blocks: Block[]): string
```

`marked` единственная внешняя зависимость. На прототипе можно подключить локальным файлом, в плагине собрать esbuild.

## 13. Критерий готовности

- 14 пунктов из раздела 10 проходят в живом черновике vc.ru.
- В теле статьи нет строк, начинающихся с `[text:`.
- Три реальных файла вставляются без ручной правки разметки, кроме картинок.
- Код конвертера не знает про Obsidian API. Это чистые функции, готовые к переезду в плагин.

## 15. Открытые вопросы

1. `text` с `<p>` внутри: проверено на первом прогоне, вставка с обёрткой работает. Оставляем `<p>`.
2. `marked` или свой парсер: выбран `marked` как лексер плюс свой сборщик инлайн-HTML. Этого хватает на MVP.
3. Запуск из консоли Obsidian: пока достаточно страницы в браузере. Консоль это шаг плагина.
4. Таблица как `code`: проверено на опубликованной статье `010`, блок сохраняется после публикации. Открытым остаётся только удобство редактирования таблицы в vc.ru.
