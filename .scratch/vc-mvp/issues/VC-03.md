## Проблема

Сейчас таблица уходит в `code` как исходный Markdown. Если в файле колонки не выровнены, в vc.ru моноширинный блок выглядит рвано:

```
| Колонка | Значение |
|---|---|
| A | 1 |
| B | 2 |
```

Хочется, чтобы перед сериализацией таблица выравнивалась по ширине колонок:

```
| Колонка | Значение |
|---------|----------|
| A       | 1        |
| B       | 2        |
```

Это косметика. На Дзене кода нет, поэтому для других площадок задача не нужна.

## Что сделать

- Разбирать `table` токен в ячейки с учётом экранированных `\|`.
- Считать ширину колонки по самой длинной ячейке и по разделителю.
- Дополнять ячейки пробелами, сохраняя выравнивание `---`, `:--`, `--:`, `:-:`.
- Собирать выровненный Markdown и отдавать его в `code` с `lang: ""`.
- Не менять исходный Markdown статьи, только payload.
- Добавить проверку 15 в прототип.

## Приёмка

- Пример из проблемы даёт выровненный блок.
- Таблица с `:---:`, пустыми ячейками и разным числом столбцов не падает.
- Экранированный `\|` внутри ячейки не ломает разбор.
- Широкие символы (CJK, эмодзи) не обязаны выравниваться идеально, это известное ограничение.
- 15 проверок зелёные в headless Chrome.
