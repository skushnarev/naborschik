## Проблема

Картинки сейчас всегда остаются строкой `![[...]]`, замена ручная. Непонятно, примет ли визуальный редактор Дзена или Смартлаба картинку из HTML. Если примет, плагин сможет вставлять фото из хранилища. Проверять это на реальном фото дорого: base64 выйдет на сотни килобайт.

## Что сделать

- Добавить в `toBlocks` необязательную карту изображений `{ images: { "star.png": "data:image/png;base64,..." } }`.
- Если имя из `![[star.png|64]]` есть в карте, делать отдельный блок `image` с `src`, `alt`, `width` и `raw`.
- Если имени нет в карте, оставить прежнее поведение: строка текстом.
- vc.ru по-прежнему получает текст картинки, без изменений.
- Дзен и Смартлаб получают `<img src="..." alt="..." width="...">`.
- Разрешать только `data:image/` и `http(s)://`, остальное оставлять текстом.
- Добавить маленькую фикстуру `prototype/fixtures/star.png` и карту в `fixtures/images.js`.
- Добавить строку с фикстурой в пример и проверку на странице.
- Обновить Node-тесты, спеку и README.

## Приёмка

- `toBlocks` без карты работает как раньше.
- С картой `![[star.png|64]]` даёт блок `image`, а vc.ru всё ещё текст.
- Дзен и Смартлаб дают `<img>` с data URI.
- Опасная схема не превращается в `<img>`.
- Node-тесты и проверки на странице зелёные.
- Живой прогон отвечает: выживает ли data URI в редакторах.

## Ход

- Карта изображений и блок `image` готовы.
- Фикстура `prototype/fixtures/star.png` была 32x32, 164 байта, data URI 242 символа. В PL-12 пересобрана на 16x16.
- Смартлаб принял `<img>` с data URI и перезалил картинку к себе: в предпросмотре появился `/uploads/.../d3dc4a.webp`.
- Дзен отклонил 16x16 с ошибкой «Изображение должно быть не менее 300 пикселей в ширину».
- Добавлена `prototype/fixtures/gray.png` 320x320, 465 байт, data URI 642 символа. Пример теперь использует `![[gray.png|300]]`.
- Повторный прогон Дзена с серой картинкой прошёл: серый квадрат появился, ошибки нет.
- 40 Node-тестов и 26/26 проверок на странице зелёные.
- Обе площадки приняли фото из data URI. Задача закрыта.
