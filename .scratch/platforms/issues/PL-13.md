## Проблема

PL-12 показал: vc.ru принимает структуру `[media:...]` и создаёт блок фото, но с условным `uuid` показывает заглушку «Not Found». Настоящий `uuid` выдаёт сервер после загрузки.

PL-14 нашёл путь без отдельной загрузки через API: если передать `<img src="data:...">` внутри `[text:...]`, vc.ru сам загружает картинку и создаёт нативный `[media:...]` с настоящим `uuid`. В прототипе этот режим убран, чтобы не держать настройку ради одной площадки. В плагине это может быть отдельная фича.

## Что сделать

- При переносе конвертера в плагин добавить режим, в котором блок `image` уходит как `[text:...]` с `<img src="data:...">`.
- Читать картинку из хранилища Obsidian и собирать data URI на стороне плагина. Конвертер остаётся чистым.
- Проверить ограничения vc.ru по размеру и формату картинки, при необходимости адаптировать изображение.
- Проверить поле описания и внешний вид: фото из data URI приходит без подписи и без скругления.
- Учесть поля реального payload `isVideo`, `duration` и `has_audio`, если понадобится собирать `[media:...]` вручную.
- Оставить загрузку через API как запасной путь, если data URI не пройдёт по размеру.
- Не добавлять переключатель в прототип: фича живёт в плагине.

## Приёмка

- Живой черновик vc.ru показывает фото, вставленное из плагина, без ручной замены.
- Конвертер по-прежнему чистые функции без сети и Obsidian API.
- Токены, cookies и личные данные не попадают в репозиторий.
- Если data URI не проходит, зафиксировано ограничение и остаётся ручная замена.
