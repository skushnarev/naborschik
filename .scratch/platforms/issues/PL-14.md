## Проблема

PL-12 показал, что `[media:...]` с условным `uuid` даёт заглушку «Not Found». Настоящий `uuid` выдаёт сервер после загрузки, а загрузки пока нет. При этом в `[text:...]` можно передать HTML. Непонятно, примет ли vc.ru `<img src="data:image/png;base64,...">` и загрузит ли картинку сам.

Если примет, фото можно вставлять без API загрузки. Если вырежет, останется только PL-13.

## Что сделать

- Добавить в `toVcruPayload` необязательный режим `imageMode: "img"`.
- В этом режиме блок `image` без `media` уходит как `[text:{"text":"<p><img src=\"...\" alt=\"...\" width=\"...\"></p>"}]`.
- По умолчанию оставить прежний текст `![[...]]`.
- Проверить живой черновик vc.ru с серой картинкой 320x320.

## Приёмка

- Без режима vc.ru получает прежний текст.
- С режимом vc.ru получает `<img>` с data URI и без `[media:...]`.
- Дзен и Смартлаб не меняются.
- Живой прогон отвечает: появилась картинка или редактор её вырезал.

## Ход

- `toVcruPayload` принимал `imageMode: "img"`, фото уходило как `[text:...]` с `<img src="data:...">`.
- Для проверки в прототип временно добавлялась галочка «фото: img» на площадке vc.ru.
- Живой прогон: vc.ru принял `<img src="data:...">`, сам загрузил картинку и создал нативный блок `[media:...]` с настоящим `uuid`.
- Картинка в редакторе выглядит иначе, чем добавленная руками: без подписи и без скругления. Поле описания пустое. Для гипотезы это не критично, но при отдельной фиче надо проверить адаптацию.
- По обратной связи настройка «фото: img» убрана из прототипа: она работала только для одной площадки и не должна быть общей настройкой.
- Поведение стало по умолчанию: картинка из карты без готового `media` уходит как `<img>` с data URI, без переключателя.
- После возврата поведения: 40 Node-тестов и 27/27 проверок на странице зелёные.
- Задача закрыта: механизм подтверждён и включён в прототип. В плагине остаётся чтение из хранилища и адаптация, PL-13.
