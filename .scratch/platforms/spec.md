# HTML для Дзена и Смартлаба

## Зачем

Автор публикует одну статью одновременно на vc.ru, Дзене и Смартлабе. Для vc.ru уже есть рабочий `text/plain` с блоками `[tool:...]`. Дзен и Смартлаб принимают HTML, но с разными ограничениями. Нужен общий разбор Markdown и два HTML-сериализатора, чтобы верстку не собирать руками на каждой площадке.

## Что входит

- Общий `Block[]` из `toBlocks` как единственный источник данных.
- Отдельный блок таблицы: заголовки, строки, выравнивание и исходный текст.
- `toDzenHtml(blocks)` с деградациями под ограничения Дзена.
- `toSmartlabHtml(blocks)` с безопасным HTML без классов, `id` и стилей.
- Переключатель площадки в прототипе и копирование выбранного выхода.
- Node-тесты для сериализаторов и новые проверки на странице.
- Заметка по живому прогону в обоих черновиках.

## Что не входит

- Плагин Obsidian, команды, настройки и модалка.
- Загрузка картинок.
- HTML-мост для vc.ru и поддержка Windows.
- Выравнивание таблиц из VC-03.
- Телеграм, Пикабу, Хабр и другие площадки.

## Контракт выхода

HTML-фрагмент без `<html>`, `<head>` и `<body>`. Чистые функции, без DOM и Obsidian API. Для vc.ru остаётся текущий `toVcruPayload`. Для Дзена и Смартлаба прототип копирует HTML в буфер, чтобы визуальный редактор получил разметку, а не исходный текст тегов.

Вики-ссылки и картинки не разворачиваются: `[[...]]` и `![[...]]` остаются в тексте как есть во всех трёх выходах. Замена ручная, поиск по `[[` находит оба вида.

## Фото (эксперимент)

Без карты изображений поведение прежнее: `![[...]]` остаётся текстом.

Прототип передаёт в `toBlocks(markdown, { images })` карту имени файла в data URI. Если имя совпало, отдельная строка `![[star.png|64]]` становится блоком `image`:

- vc.ru получает прежнюю строку `![[...]]` текстом, без изменений;
- Дзен и Смартлаб получают `<img src="..." alt="..." width="64">`.

Разрешены только `data:image/` и `http(s)://`, остальные схемы остаются текстом. Карта это тестовая фикстура `prototype/fixtures/`, а не загрузка из хранилища Obsidian. Выживет ли data URI после вставки в редакторы, покажет живой прогон.

## Общая модель блоков

`header`, `text`, `list`, `quote`, `code`, `table`, `delimiter`.

Таблица больше не маскируется под `code`. Это нужно, чтобы vc.ru получал прежний `[code:...]`, а Дзен мог развернуть таблицу в список, а Смартлаб попробовать нативный `<table>`.

## Дзен

Поддерживаемые элементы: `h2`, `h3`, `p`, `b`, `i`, `s`, `a`, `ul`, `ol`, `blockquote`, `br`.

Деградации:

- Блок кода становится `blockquote` с сохранением строк через `<br>`. Если живой редактор вырежет цитату, заменить на абзац с моноширинным текстом.
- Таблица становится списком пар «заголовок: значение». Для двух колонок это одна пара на строку, для широких таблиц пары разделяются точкой с запятой.
- `delimiter` становится абзацем `* * *`.
- H4-H6 уже приходят жирным абзацем из общего разбора.
- Вложенные списки уже плоские, вложенность показывает маркер `↳`.
- Картинки остаются строкой `![[...]]`, замена ручная.
- Вики-ссылки остаются строкой `[[...]]`, замена ручная.

## Смартлаб

Безопасный набор: `p`, `h3`, `b`, `i`, `s`, `a`, `ul`, `ol`, `blockquote`, `br`, без классов, `id`, `style` и Obsidian-атрибутов.

Проверено живым черновиком:

- Блок кода отдаём как `<pre>` без вложенного `<code>`. Санитайзер показывает тег `code` текстом.
- Таблицу отдаём как `<table>` с `<thead>` и `<tbody>`. Санитайзер срезает `thead`, но `th` остаются в `tbody`, заголовок таблицы виден.
- `delimiter` отдаём как `<hr>`. Разделитель выживает.
- `b` и `i` после санитайзера становятся `strong` и `em`. Это нормально.
- H2 отдаём как `<h3>`, H3 как `<h4>`. `<h2>` санитайзер вырезает и оставляет голый текст. В визуальном редакторе площадки есть только H3 и H4, поэтому два уровня Markdown ложатся в них.
- Маппинг идёт по исходному `block.style` за один проход. Строковых замен нет, каскада h2→h3→h4 не возникает.
- H4-H6 уже приходят жирным абзацем из общего разбора и отдельных тегов не требуют.

Непроверенное заменяется деградацией, а не догадкой. Решение принимается по заметке живого прогона.

## Проверки

- 14 проверок vc.ru остаются зелёными.
- Новые проверки: заголовок Дзена, деградация кода и таблицы в Дзене, разделитель Дзена, код и таблица Смартлаба, экранирование.
- Node-тесты на таблицу, ссылки, списки и отсутствие сырых тегов.
- Живой прогон одной реальной статьи в обоих черновиках.

## Критерий готовности

- В прототипе один вход и три выхода: vc.ru, Дзен, Смартлаб.
- Выбранный выход копируется одной кнопкой.
- Выход vc.ru не изменился.
- HTML-функции чистые и детерминированные.
- `make check` и проверки на странице зелёные.
- Расхождения живого прогона записаны в `.scratch/platforms/notes/`.

## Открытые вопросы

- Дзен: цитата для длинных листингов. Первый проход принят, вернуться, если будет мешать.
- Широкие таблицы: сколько пар в одном пункте списка терпимо для читателя.
- Смартлаб: `h4` в предпросмотре выглядит скромнее `h3`, хотя тег выживает. Проверить на опубликованной странице, если понадобится.
