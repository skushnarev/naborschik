# Живой прогон 3: картинки после перезагрузки

Дата: 2026-11-24
Вход: пример из прототипа с `![[BLG016_top.jpg|800]]` и `![[gray.png|300]]`.
Метод: вставить всю статью из прототипа, затем отдельно вставить только `gray.png`, сравнить разметку блоков и проверить черновик после обновления страницы.

## Дзен

Оба блока пришли одинаковой нативной разметкой `figure.zen-editor-block-image` с `data-block="true"`. Внутри одинаковая картинка, перезалитая на `avatars.dzeninfra.ru`, и одинаковое поле подписи:

```html
<div class="article-editor-desktop--article-image-caption__caption-1B ...">
  <span class="...captionPlaceholder...">Добавьте описание</span>
  <textarea class="...image-caption__input..." placeholder="Добавьте описание" maxlength="2000"></textarea>
</div>
```

Различаются только идентификаторы загрузки в адресах картинок: это две отдельные вставки одного файла. Атрибуты `data-darkreader-*` в первом блоке добавило расширение Dark Reader, к Дзену они отношения не имеют.

Черновик переживает обновление страницы: картинка и поле описания остаются на месте.

Вывод: на Дзене data URI даёт ровно тот же нативный блок, что и ручная вставка. Отдельно картинки вставлять не нужно.

## Смартлаб

При вставке всей статьи и при вставке одной картинки появляется тост про загрузку. Оба раза картинка перезаливается к себе:

```html
<a class="imgpreview" href="/uploads/2026/images/30/56/96/2026/11/24/086c31.png"><img src="/uploads/2026/images/30/56/96/2026/11/24/7b63b4.webp"><br><br><br></a>
<a class="imgpreview" href="/uploads/2026/images/30/56/96/2026/11/24/d40d4b.png"><img src="/uploads/2026/images/30/56/96/2026/11/24/792b00.webp"></a>
<a class="imgpreview" href="/uploads/2026/images/30/56/96/2026/11/24/086c31.png"><br><br></a>
```

Первые два адреса это две разные загрузки. Третий пустой `<a class="imgpreview">` ссылается на первую картинку и, похоже, остался от плейсхолдера загрузки. Надо проверить, исчезает ли он после сохранения и перезагрузки, и не даёт ли лишний отступ на опубликованной странице.

Вывод: на Смартлабе data URI рабочий, но остаётся проверить пустой якорь и сохранение.

## vc.ru

При вставке картинка появляется, vc.ru сам загружает её и создаёт нативный блок с настоящим `uuid`. Но после обновления страницы картинка исчезает. Значит, путь держится только на состоянии редактора и не сохраняется в черновике.

Вывод: для vc.ru data URI негоден. Строка картинки остаётся текстом `![[gray.png|300]]`, фото автор вставляет вручную. Нативный блок возможен только с готовым `uuid`, а его без загрузки через API взять негде.

## Итог

- Дзен: картинки через буфер, нативный блок с подписью, переживает перезагрузку.
- Смартлаб: картинки через буфер, площадка перезаливает к себе; проверить пустой якорь.
- vc.ru: картинки вручную, в тексте остаётся строка `![[...]]`.
