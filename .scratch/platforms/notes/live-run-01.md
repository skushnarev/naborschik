# Живой прогон 1: Дзен и Смартлаб

Дата: 2026-11-23
Статус: Дзен и Смартлаб проверены, обе правки внесены.
Вход: пример из прототипа и реальная статья `016`.
Метод: открыть `prototype/index.html`, выбрать площадку, нажать «Скопировать» и вставить в визуальный редактор.

## Что проверить

Для каждой площадки пройти одни и те же элементы:

| Элемент | Ожидание | Факт | Решение |
|---|---|---|---|
| H2 | заголовок | | |
| H3 | подзаголовок | | |
| Абзац с `b`, `i`, ссылкой | разметка на месте | | |
| UL и OL | нативные списки | | |
| Вложенный список | плоский список с `↳` | | |
| Цитата | blockquote | | |
| Код | Дзен: цитата. Смартлаб: `pre/code` | | |
| Таблица | Дзен: список пар. Смартлаб: `table` | | |
| Разделитель | Дзен: `* * *`. Смартлаб: `hr` | | |
| Картинка | строка `![[...]]`, замена ручная | | |
| Экранирование | `<script>` виден текстом | | |

## Отдельно проверить

- Пришёл ли HTML размеченным или редактор вставил теги текстом.
- Не склеил ли редактор соседние абзацы.
- Не потерялись ли ссылки и пустые строки.
- Не вырезал ли санитайзер `pre`, `code`, `table` и `hr`.
- Как выглядит длинная статья: нет ли заметной задержки.

## Дзен: результат

| Элемент | Факт |
|---|---|
| Вставка HTML | разметка пришла, теги текстом не вставились |
| H2 и H3 | заголовки на месте |
| Абзац с `b`, `i`, ссылкой | жирный, курсив и ссылка сохранились |
| UL и OL | нативные списки |
| Вложенный список | плоский список с `↳` |
| Цитата и callout | blockquote, заголовок жирным |
| Код | цитата с сохранением строк, читается нормально |
| Таблица | список пар «заголовок: значение» |
| Разделитель | текст `* * *` |
| Картинка | строка `![[...]]`, замена ручная |
| Ссылка на заметку | осталась текстом с алиасом |

Реальная статья `016` встала целиком, микроразметка с жирным в тексте сохранилась. Это тот случай, где раньше была ручная работа.

Копирование из черновика Дзена обратно отдаёт только текст без разметки. Это ограничение редактора, а не нашего выхода. Для Смартлаба надо брать HTML из прототипа, а не копировать из Дзена.

Код цитатой принят для первого прохода. Если на длинных листингах будет мешать, заведём отдельную задачу на другой вид деградации.

## Смартлаб: результат

HTML в редакторе выглядит правильно. Редактор показывает исходный HTML:

```html
<h2>Глава 1</h2>
<h3>Раздел</h3>
<p>Абзац с <strong>жирным</strong>, <em>курсивом</em>, <a href="https://ya.ru/">ссылкой</a> и кодом.</p>
<blockquote><p><strong>Важно</strong><br />Callout превращается в цитату.</p></blockquote>
<ul><li>Первый пункт</li></ul>
<ol><li>Первый</li></ol>
<hr />
<table><thead><tr><th>Колонка</th><th>Значение</th></tr></thead><tbody>...</tbody></table>
<pre><code>const x = 1;</code></pre>
```

| Элемент | Факт | Решение |
|---|---|---|
| Вставка HTML | приходит разметкой, теги текстом не вставились | оставить |
| H2 и H3 | в редакторе верно, в старом предпросмотре ломаются | проверить опубликованный пост, PL-08 |
| `strong`, `em`, ссылки | санитайзер заменил `b`/`i` на `strong`/`em`, ссылка на месте | оставить |
| UL и OL | списки на месте | оставить |
| Цитата и callout | blockquote с `<br />` | оставить |
| Код | `<pre><code>` показывает теги `<code>` текстом внутри блока | убрать `<code>`, PL-07 |
| Таблица | таблица на месте, но узкая | оставить |
| Разделитель | `<hr />` на месте | оставить |
| Картинка | строка `![[...]]`, замена ручная | оставить |

Старый редактор в предпросмотре ломает заголовки, хотя в HTML они верные. Это похоже на CSS предпросмотра, а не на ошибку выхода. Публичные посты Смартлаба используют `<h3>` в теле статьи: например `https://smart-lab.ru/blog/1378563.php`, блоки `ОФЗ 26233` и далее. Поэтому `h2`/`h3` пока не деградируем: нужен один живой пост или DOM предпросмотра.

Новый редактор Смартлаба показывает только HTML без предпросмотра. Проверять верстку можно по старому редактору или по опубликованному черновику.

## Смартлаб: DOM предпросмотра

Пришёл HTML блока `#text_preview`. Главное:

```html
</p>Глава 1<p>
...
<hr><h3>Раздел</h3>
<table><tbody><tr><th>Колонка</th><th>Значение</th></tr>...
<pre>const x = 1;
const y = 2;</pre>
```

| Что было | Что стало | Вывод |
|---|---|---|
| `<h2>Глава 1</h2>` | `Глава 1` без тега | `h2` вырезается, PL-08 |
| `<h3>Раздел</h3>` | `<h3>Раздел</h3>` | `h3` выживает |
| `<pre><code>...</code></pre>` | `<pre>...</pre>` | PL-07 сработал, тегов `code` больше нет |
| `<table><thead>...` | `<table><tbody><tr><th>...` | `thead` срезан, `th` остались в `tbody` |
| `<a href="https://ya.ru">` | `<a href="/r.php?u=...">` | редирект площадки, ссылка рабочая |

Публичные посты Смартлаба за последние 40 записей используют в теле только `<h3>`: 5 постов с заголовками, все на `h3`. `h2` и `h4` в теле не встречаются.

В визуальном редакторе площадки в выпадающем списке заголовков есть только H3 и H4. Значит, `h2` площадке недоступен, а два уровня Markdown можно разложить в `h3` и `h4`.

Повторный прогон после PL-09 это подтвердил:

```html
<h3>Глава 1</h3>
...
<h4>Раздел</h4>
...
<pre>const x = 1;
const y = 2;</pre>
```

`h3` и `h4` выжили, `<h2>` и `<code>` в предпросмотре нет. Визуально `h4` в предпросмотре скромнее `h3`, но тег на месте, а публичные страницы стилизуют заголовки по-своему.

## Итог

Дзен принят. Смартлаб принят с двумя правками:

- PL-07: код отдавать как `<pre>` без вложенного `<code>`. Готово, предпросмотр подтвердил.
- PL-08: `h2` площадка вырезает, поэтому заголовки больше не уходят как `<h2>`.
- PL-09: H2 отдаём как `<h3>`, H3 как `<h4>`. Это два уровня, которые есть в редакторе площадки. Живой предпросмотр подтвердил, что оба тега выживают.

Остальные элементы после санитайзера выжили. `thead` срезается, но `th` остаются и заголовок таблицы виден. Обе площадки приняты.
