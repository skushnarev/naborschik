# Прототип конвертера

Вопрос, на который отвечает эта папка: можно ли из одной статьи в Obsidian получить верстку для vc.ru, Дзена и Смартлаба без ручной сборки блоков.

Это не плагин и не продакшен-код. Прототип нарочно одноразовый: одна страница, чистые функции, никакого Obsidian API.

## Запуск

```bash
make prototype
```

Или открыть `prototype/index.html` двойным кликом. Сборка и сеть не нужны: `marked` лежит в `vendor/`.

## Что внутри

- `index.html` - разметка и стили.
- `converter.js` - чистый конвертер: `toBlocks(markdown)`, `toVcruPayload(blocks)`, `toDzenHtml(blocks)` и `toSmartlabHtml(blocks)`.
- `app.js` - тонкая оболочка: textarea, выбор площадки, предпросмотр, буфер обмена, 26 самопроверок.
- `vendor/marked.umd.js` - `marked` 18.2.1, MIT. Лицензия рядом.

`marked` используется только как лексер. HTML собираем сами, чтобы контролировать теги, экранирование и Obsidian-разметку.

## Что проверяет страница

- 16 краевых случаев vc.ru, спецразметки и фото из раздела 10 спеки.
- 10 проверок HTML для Дзена и Смартлаба: заголовки, код, таблицы, разделители, экранирование.
- Реальные статьи `016`, `010`, `017` через кнопку «Открыть .md».
- Одиночный блок в vc.ru: уходит текстом, а не `[tool:...]`; исключение это фото с `media`.
- Frontmatter, комментарии, вики-ссылки, callout-ы, вложенные списки, код и таблицы.
- Фото из карты: vc.ru получает `[media:...]`, Дзен и Смартлаб получают `<img>`.
- Вики-ссылки `[[...]]` и картинки вне карты остаются текстом: поиск по `[[`.

## Тесты

```bash
make test
```

Node-тесты лежат в `prototype/tests/` и проверяют конвертер без браузера.

## Что выяснилось на живом прогоне

- vc.ru срезает ведущие пробелы и `&nbsp;` в пунктах списка. Вложенность показываем маркером `↳`, а не отступом.
- У цитаты с пустым `subline1` в черновике видна серая подпись «Подпись». Похоже на плейсхолдер редактора, но это надо проверить после публикации.
- vc.ru понимает нативные блоки кода: `[code:{"text":"...","lang":"javascript","lineWrapping":false}]`.
- Таблица уходит одним `code` с Markdown-текстом и `lang: ""`. Это моноширинный блок, а не нативная таблица, но лучше развалившихся абзацев.
- Картинки остаются строкой текста, как и задумано в MVP.

Подробности: `.scratch/vc-mvp/notes/live-run-01.md`.

## Дзен и Смартлаб

- Дзен получает HTML: код становится цитатой, таблица списком, разделитель текстом.
- Смартлаб получает HTML: код идёт через `pre` без вложенного `code`, таблица через `table`, разделитель через `hr`. Живой черновик подтвердил, что эти теги выживают.
- Заголовки Смартлаба идут как `h3` и `h4`: `h2` площадка вырезает, а в редакторе есть только эти два уровня. Проверка в `.scratch/platforms/notes/live-run-01.md`.

## Фото

В `fixtures/` два файла. `star.png` 16x16 на 106 байт с `media` нужен для проверки vc.ru. `gray.png` 320x320 на 465 байт без `media` стоит в примере: Дзен требует ширину от 300 пикселей. Серая заливка сжимается в data URI на 642 символа.

Для `star.png` vc.ru получает `[media:...]` с условным `uuid`, для `gray.png` остаётся строкой `![[...]]`. Дзен и Смартлаб получают `<img src="data:image/png;base64,...">`.

Живой прогон: Смартлаб принял data URI и перезалил картинку к себе. Дзен отклонил 16x16 с ошибкой «Изображение должно быть не менее 300 пикселей в ширину», поэтому в примере теперь `gray.png`. vc.ru принял структуру `[media:...]`, но с условным `uuid` показал заглушку «Not Found». Настоящий `uuid` выдаёт сервер vc.ru после загрузки файла.

В карточке блока `image` видна сама картинка, а раскрытый payload показывает `alt`, `width` и краткие метаданные без полного base64.

Реальные имена вроде `BLG016_top.jpg` в карте отсутствуют и остаются текстом.

## Чего здесь нет

- Загрузки картинок из хранилища Obsidian.
- HTML-моста для Windows.
- Настроек, команд Obsidian и модалки.

После живой проверки конвертер переезжает в `src/` плагина, а эта папка остаётся снимком гипотезы.
