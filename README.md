# naborschik

Плагин для Obsidian: превращает Markdown статьи в блоки vc.ru и HTML-фрагменты для Дзена и Смартлаба. Выделение или заметка целиком разбираются один раз, выбранный адаптер площадки кладёт готовый выход в буфер.

## Установка и сборка

```bash
npm install
make plugin-link VAULT=/путь/к/хранилищу
```

Цель собирает плагин в `dist/` и ставит симлинк `<хранилище>/.obsidian/plugins/naborschik` на эту папку. Дальше в Obsidian включить сторонние плагины и `naborschik`. После правок выполнить `make build` или держать `make dev`, потом перезагрузить плагин или нажать `Cmd+R`.

Команды `Копировать для vc.ru`, `Копировать для Дзена` и `Копировать для Смартлаба` есть в палитре, а в меню редактора они собраны в подменю. Если Obsidian не умеет подменю, вместо него появляются плоские пункты. Выделение важнее заметки целиком: пустое выделение берёт весь файл. Frontmatter и H1 отбрасываются, заголовок статьи вставляется в поле заголовка вручную.

## Три выхода

| Площадка | Формат буфера | Что получается |
|---|---|---|
| vc.ru | `text/plain` | Блоки `[text:{...}]`, `[header:{...}]`, `[list:{...}]`, `[quote:{...}]`, `[code:{...}]`, `[delimiter:{...}]` через пустую строку. Одиночный блок уходит читаемым текстом. |
| Дзен | `text/html` и `plain` | H2 и H3 как есть, код цитатой, таблица списком пар, разделитель абзацем. |
| Смартлаб | `text/html` и `plain` | H2 как h3, H3 как h4, код в `pre` без `code`, таблица таблицей. |

У HTML-выходов `plain` остаётся читаемым текстом без тегов: он нужен, если rich-вставка недоступна. Картинки не загружаются на площадки, но читаются из хранилища: Дзен и Смартлаб получают `img` с data URI и шириной, vc.ru получает строку `![[...]]` текстом, замена ручная. Ненайденный файл оставляет текст и даёт предупреждение. Пустая заметка не затирает буфер и даёт уведомление `Нечего копировать`. Успешное копирование показывает число символов и предупреждений, первая причина и ссылка `Подробнее` объясняют, что править. Подробности предупреждений по-прежнему идут в консоль.

## Веб-версия конвертера

```bash
make public
```

Собирает `public/index.html`: один самодостаточный файл со встроенными стилями и скриптами. Он открывается двойным кликом, без Obsidian, сервера и запросов в сеть. Внутри те же `parse` и `PLATFORMS`, что в плагине: поле Markdown, три площадки, предпросмотр блоков, payload и копирование. Заголовок статьи в буфер не входит. Картинки выбираются кнопками «Добавить картинки» и «Папка» или перетаскиванием на страницу: файлы читаются в память и сопоставляются с `![[...]]` по пути и уникальному имени. Дзен и Смартлаб получают `img` с data URI, vc.ru оставляет строку текстом. Одинаковые имена дают предупреждение и не подставляются, ненайденные вставки остаются текстом. После перезагрузки файлы выбираются заново: Markdown тоже не сохраняется. Собранный `public/` не коммитится, в репозитории только исходники `web/`. Хостинг и деплой это `WEB-03`.

## Контракт адаптера

Разбор и адаптеры не импортируют Obsidian, поэтому проверяются в Node. Граница проходит по двум швам: `parse` превращает Markdown в `Document`, `convert` адаптера превращает документ в `ClipboardPayload`.

```ts
interface PlatformAdapter {
  id: string;
  title: string;
  forWhom: string;
  icon: string;
  convert(doc: Document, ctx: ConvertContext): Promise<ClipboardPayload>;
}
```

Источник истины по типам: `src/core/types.ts`. Здесь показана только граница адаптера, `Document`, `ClipboardPayload`, `ConvertContext`, `Warning` и `ImageResolver` описаны там же.

- `plain` обязателен и это то, что реально попадает в `text/plain`: tool-блоки у vc.ru или читаемый текст без тегов у Дзена и Смартлаба. `html` заполняется только у площадок, которые принимают разметку.
- `forWhom` это форма для фразы `Копировать для ...` и уведомления, `title` и `icon` идут в меню.
- `convert` асинхронный: загрузка картинок на площадку останется асинхронной. Чтение файлов из хранилища делает обвязка до разбора, поэтому `parse` синхронный.
- Деградации и неразрешённые картинки пишутся в `ctx.warnings`. Пустой результат это не предупреждение: обвязка проверяет документ до конвертации.
- `Block` описан в `src/core/types.ts`. Новый тип блока обязателен во всех адаптерах, иначе тест инвариантов упадёт.

## Как добавить площадку

1. Создать `src/platforms/<id>.ts` и экспортировать объект `PlatformAdapter`.
2. Добавить адаптер в упорядоченный реестр `PLATFORMS` в `src/platforms/index.ts`. Меню и палитра строятся из него, отдельная регистрация не нужна.
3. Создать `test/<id>.test.ts` с golden-выходом и прогнать документ со всеми типами блоков через новый адаптер. Фикстуры площадки соберёт `make golden`: генератор берёт площадки из `PLATFORMS`.
4. Добавить id площадки в список ожидаемых в `test/platforms.test.ts`: этот тест фиксирует порядок меню и падает на новой площадке.
5. Добавить подсказку для площадки в `hintFor` в `web/main.ts`, если она нужна. Список площадок веб-конвертер берёт из `PLATFORMS` сам.
6. Выполнить `make check`. Разбор и реестр не меняются, регистрация живёт в реестре и тесте реестра.

  main.ts                 интерфейс: ввод, картинки, площадки, блоки, payload, копирование

Остальное в репозитории:

- `docs/` - процессы, решения и правило недокументированного API.
- `.scratch/` - спеки и задачи эпиков.
- `bin/` - проверки задач, документации, чистоты ядра, сборка golden и веб-конвертера.
- `.agents/` - скиллы и слэш-команды.

## Задачи

Задачи и спеки это markdown-файлы в `.scratch/`. Одна фича или эпик - одна директория, спека в `spec.md`, задачи в `issues/`. Статус хранится во front matter задачи, а не в тексте документа.

```bash
make status
make status ARGS="--all"
make status ARGS="--area vc-converter"
make status ARGS="--check"
```

Правила и формат: `docs/agents/issue-tracker.md`.

## Проверки

```bash
npm install
make docs-check
make core-check
make test
make check
make hooks
```

`make test` гоняет тесты плагина и веб-сборки. `make core-check` проверяет, что ядро, адаптеры и веб-конвертер не импортируют Obsidian. `make check` добавляет к ним типы, тесты и сборку плагина. `make hooks` ставит pre-commit с `make check`.

`docs-check` проверяет front matter, ссылки, циклы блокировок и запрещает чеклисты и статусные таблицы в нарративных документах. `make golden` пересобирает golden-фикстуры из `src/`: запускать после правки `article.md` или осознанного изменения выходов.

## Скиллы

Скиллы лежат в `.agents/skills/`, команды в `.agents/commands/`. Адаптер OpenCode это симлинк `.opencode/commands -> ../.agents/commands`, его создаёт одна команда после клонирования:

```bash
make agents
```

Источник и порядок обновления: `docs/skills/ADOPTION.md`.
