# naborschik

Плагин для Obsidian под рабочим названием `naborschik`: превращает Markdown статьи в блоки для vc.ru и HTML для Дзена и Смартлаба.

Сейчас это прототип. Конвертер проверяет, что одну статью из Obsidian можно разложить на три площадки без ручной сборки верстки. Плагин-заглушка проверяет механику Obsidian: выделение, команды, буфер и уведомление.

## Что внутри

- `prototype/` - одноразовый конвертер: textarea, выбор площадки, предпросмотр и 27 самопроверок.
- `prototype/obsidian/` - плагин-заглушка: команды палитры, префикс площадки, буфер.
- `.scratch/vc-mvp/` - спека гипотезы vc.ru и задачи эпика.
- `.scratch/platforms/` - спека HTML-выходов для Дзена и Смартлаба.
- `.scratch/plugin-prototype/` - спека и задачи механики плагина.
- `.agents/skills/` - вендор скиллов `mattpocock/skills`.
- `.agents/commands/` - слэш-команды, собранные из скиллов.
- `docs/` - процессы, решения, заметки по скиллам.
- `bin/` - проверки задач и документации.

## Прототип

```bash
make prototype
```

Откроется `prototype/index.html`. Дальше:

1. Выделить статью в Obsidian без H1, скопировать.
2. Вставить Markdown в левое поле.
3. Выбрать площадку: `vc.ru`, `Дзен` или `Смартлаб`.
4. Проверить выход и нажать «Скопировать».
5. Для vc.ru поставить курсор в пустой текстовый блок и вставить. Для Дзена и Смартлаба вставить HTML в визуальный редактор.
6. Заголовок статьи вписать в поле заголовка вручную.

Если открыть файл двойным кликом, тоже работает: `marked` лежит рядом в `prototype/vendor/`.

## Плагин

```bash
make plugin-link VAULT=/путь/к/хранилищу
```

Цель ставит симлинк в `<хранилище>/.obsidian/plugins/naborschik`. Дальше в Obsidian включить сторонние плагины и `naborschik`. После правок переключить плагин или нажать `Cmd+R`.

Пока это заглушка без конвертера: три команды `Копировать для vc.ru`, `Копировать для Дзена` и `Копировать для Смартлаба` кладут в буфер `Для <площадка>`, пустую строку и выделение как есть. Подробности и откат: `prototype/obsidian/README.md`.

## Задачи

Задачи и спеки это markdown-файлы в `.scratch/`. Одна фича или эпик - одна директория, спека в `spec.md`, задачи в `issues/`. Статус хранится во front matter задачи, а не в тексте документа.

```bash
make status
make status ARGS="--all"
make status ARGS="--area vc-converter"
make status ARGS="--check"
```

Правила и формат: `docs/agents/issue-tracker.md`.

## Проверки

```bash
make docs-check
make test
make check
```

`docs-check` проверяет front matter, ссылки, циклы блокировок и запрещает чеклисты и статусные таблицы в нарративных документах.

## Скиллы

Скиллы лежат в `.agents/skills/`, команды в `.agents/commands/`. Адаптер OpenCode это симлинк `.opencode/commands -> ../.agents/commands`, его создаёт одна команда после клонирования:

```bash
make agents
```

Источник и порядок обновления: `docs/skills/ADOPTION.md`.
