# Трекер задач: `.scratch/<feature>/issues/`

Задачи и спеки этого репозитория живут как markdown-файлы в `.scratch/`. Внешнего трекера нет: проект локальный, push только по согласованию.

## Раскладка

- Одна фича или эпик - одна директория: `.scratch/<feature>/`.
- Спека: `.scratch/<feature>/spec.md`. Если в фиче есть задачи, спека обязательна: она объясняет, зачем эта группа и что в неё не входит. `docs-check` это проверяет.
- Задачи: `.scratch/<feature>/issues/<имя>.md`, по одной задаче на файл.
- Канонический ID - поле `id` во front matter (`VC-01`, `VC-02`). Имя файла может быть человекочитаемым или совпадать с ID, ID всё равно читается из front matter.
- Задача ссылается на спеку через `spec:`, спека перечисляет задачи по ID.

Эти файлы коммитятся вместе с кодом: они часть истории решений, а не временный мусор. Секреты, персональные данные и доступы в задачи не попадают.

## Front matter

```markdown
---
id: VC-01
title: "Собрать наивный прототип конвертера"
status: doing
area: vc-converter
kind: feature
severity: P0
milestone: mvp
blocked_by: []
spec: .scratch/vc-mvp/spec.md
updated: 2026-11-23
---

## Проблема
...

## Что сделать
...

## Приёмка
...
```

Обязательные поля: `id`, `title`, `status`, `area`, `kind`, `updated`.
Дополнительные: `severity` (`P0`-`P3`), `milestone`, `blocked_by`, `spec`, `resolution`.

## Статусы

| Статус | Значение |
|---|---|
| `todo` | не начато, блокера нет |
| `doing` | в работе |
| `done` | проверено и принято |
| `blocked` | нужен человек или внешний блокер |

У `done` может быть `resolution`:

- `fixed` - исправлено (значение по умолчанию);
- `wontfix` - осознанно не делаем;
- `accepted` - известное ограничение;
- `duplicate` - уже покрыто другой задачей;
- `obsolete` - устарело.

У `blocked` обязателен `blocked_by`: `[human]` или ID задач, которые нужно закрыть. У остальных статусов `blocked_by` не заполняется.

## Milestone

`milestone` задаёт горизонт:

- `mvp` - проверка гипотезы: прототип, живой прогон, список правок;
- `next` - плагин Obsidian: команды, настройки, модалка;
- `later` - другие площадки и эксперименты.

`make status` показывает milestone колонкой `MILESTONE`; фильтр - `--milestone`. Колонки таблицы подстраиваются под содержимое. Итог под таблицей считается по всей выборке, включая скрытые `done`; сколько строк скрыто, сообщает подсказка `Скрыто done`.

## Команды

```bash
make status                         # todo + doing + blocked
make status ARGS="VC-01..VC-05"     # диапазон, показывает и done
make status ARGS="--all"            # включая done
make status ARGS="--area vc-converter"  # по эпику
make status ARGS="--kind feature"
make status ARGS="--milestone mvp"
make status ARGS="--status blocked"
make status ARGS="--json"
make status ARGS="--check"          # схема, ссылки, циклы
make docs-check                     # задачи + запрет чеклистов в доках
```

`make check` включает `docs-check`.

## Живая проверка

Проверка, которую нельзя сделать в Node (вставка в площадку, запуск в хранилище, поведение Electron), идёт отдельной задачей с `kind: verification`. Такая задача держится в `doing`, пока человек не подтвердит результат. Зелёные тесты и готовый код её не закрывают.

## Правила

- Не добавлять в `docs/`, `PLAN.md`, `README.md`, `AGENTS.md`, `GLOSSARY.md` и спеки чеклисты, строки `Status:` и таблицы задач со статусами. Статус читается только скриптом.
- В прозе ссылаться на ID: `VC-01`, `VC-02`. Это не запрещено и не дублирует статус.
- Новую задачу заводить в `issues/` ближайшей фичи; если фичи нет - создать директорию и `spec.md`.
- Не дублировать задачу: если работа уже покрыта, закрыть новую как `done` + `resolution: duplicate` и указать исходный ID в теле.
- После изменения статуса обновлять `updated`.
- Коммит относится к одной задаче. Планирование эпика (`spec.md` и несколько задач) идёт без ID задачи, диапазон ID в заголовке не ставим. Полные правила в `AGENTS.md`.

## Когда скилл говорит «publish to the issue tracker»

Создать файл в `.scratch/<feature>/issues/`, при необходимости создав директорию и `spec.md`. Заполнить front matter и короткое тело: проблема, что сделать, приёмка.

## Когда скилл говорит «fetch the relevant ticket»

Прочитать файл по ID: `node bin/status.mjs <ID>` покажет путь и статус, затем открыть файл.

## Wayfinder

- **Карта**: `.scratch/<effort>/map.md` (заметки, решения, «туман»).
- **Дочерняя задача**: `.scratch/<effort>/issues/<имя>.md`; вопрос в теле.
- **Блокировки**: `blocked_by` во front matter. Задача разблокирована, когда все перечисленные задачи в статусе `done`.
- **Frontier**: открытые, разблокированные и не занятые задачи; выигрывает меньший ID.
- **Claim**: поставить `status: doing` и сохранить файл до начала работы.
- **Resolve**: дописать итог, поставить `status: done` и `resolution`, обновить `updated`, добавить указатель в `map.md`.
