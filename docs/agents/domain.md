# Domain docs

Как инженерные скиллы читают доменную документацию этого репозитория.

## Перед исследованием прочитать

- `GLOSSARY.md` в корне.
- `docs/adr/`: решения, которые касаются области работы.

Если файлов нет, идти дальше молча. `/domain-modeling` создаёт их лениво, когда термин или решение действительно зафиксировано.

## Раскладка

Single-context, без `GLOSSARY-MAP.md`:

```text
/
├── GLOSSARY.md
├── docs/adr/
└── .scratch/
```

## Словарь

Когда в спеке, задаче, гипотезе или тексте появляется доменное понятие, использовать термин из `GLOSSARY.md`. Не подменять синонимами, которые глоссарий разводит.

Если понятия в глоссарии нет, это сигнал: либо язык придуман, либо есть реальный пробел. Пробел закрывается через `/grill-with-docs`.

## Конфликт с ADR

Если решение противоречит ADR, сказать об этом явно, а не переопределять молча:

> Противоречит ADR-0001 (<название>), но стоит пересмотреть, потому что...
